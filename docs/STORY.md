# Story Bible

## v0.1.0 工程片段

到达站台 → 许澄出现 → 对话 → 共伞 / 独自等雨 → 不同回应 → 片段结束 → 主菜单。

这是临时台词，用于验证工程链路，不计入正式游戏时长。

## v0.2.0 样片提案

雨夜重逢 → 谈起停运与旧事 → 选择如何回应 → 找到旧信 → 是否说明信的来历 → 共同面对离别 → 是否同行 → Normal / True 片段结局。

三个选择改变 affection / trust / truth_known。True 要求关系与信任达到阈值且知道旧信真相；其他组合到 Normal。两个结局都保留女主主动性。

v0.2 已落地 8 场景。True 条件为 affection >= 2、trust >= 1、truth_known == True；在当前三个二选一中，关心近况 + 说明信的来历 + 一起同行到 True，其余七种组合到 Normal。每个选择都有状态变化和不同对白。

全分支共约 2,600 字；单次可达路线约 1,740–1,900 汉字。按 250–350 汉字/分钟，另留选择与画面停留时间，预估 6–9 分钟，属于 5–10 分钟样片目标；不是完整游戏，也不是已经完成的真人时长测试。

剧情事实来源：`game/data/story.json`。每段含场景 ID、地点、时间、台词 ID、角色、资产、音频和下一节点。`game/script/story_generated.rpy` 只作为编译产物。

时长按可达路线字数估算，并记录估算假设。真实阅读时长必须由玩家试玩确认。

## 人工检查

检查称呼、角色动机、时间顺序、选择的可理解性、关系是否跳跃以及两种结局是否都成立。机械 linter 仅提示重复、长句、占位符、数据错误；不能取代剧本审阅。

## v0.4.0 章节路线候选

六章：序章：雨夜 → 重逢 → 旧信 → 空白 → 今天 → 雨停之前。26 节点包括两个纯状态路由；一次经过 19–20 节点。场景表见 STORY_OUTLINE_V04.md。

四次选择按 q01、q02、q04、q03 顺序游玩，保留旧 ID。每个选项都改变状态并进入独立后续场景；中段另按 trust 选择开放或保留的对话。q04 明确表达可以修复一次早期回避；先约下次联系则保留尚未坦白的事实。

True 条件改为：选择同行，且 affection >= 2、trust >= 2、truth_known == True。16 条完整路线中四条 True、十二条 Normal；选择分别绕过数值判定，始终到 Normal。状态定义写入 JSON；truth_known 表示许澄知道信的作者，玩家从序章就知道。

全分支约 7,000 字，单路线约 5,050–5,350 字，按每分钟 250–350 字并留选择停顿预估 17–24 分钟，尚未真人计时。未达到最终字数与时长。原有 6 句关键语音不变，新段落以文字呈现，更多背景/CG 在资产阶段补充。

每个新场景单独起草、保存 Prompt 和哈希，并逐段检查合流处的知识与物品状态；审阅详见 STORY_REVIEW_V04.md。章节卡使用引擎原生 centered，存读档恢复章节、实际访问路径与显示表情。没有新增剧情 Runtime 或实时生成系统。
