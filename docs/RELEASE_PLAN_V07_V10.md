## 3. v0.7：完整剧情 Alpha

目标：交付一份从开场到两个完整结局都成立的候选作品，补足时长与场景体验。

### 范围

技术继续固定 Ren'Py 8.5.3。`game/data/story.json` 是唯一剧情事实来源，使用现有 `tools.compile_story` 与 `tools.compile_tests` 再生成原生 DSL 和交互用例；引擎负责回退、存档与界面，不新增剧情运行框架。

沿用一个成年女主、第一人称玩家、六章、q01 / q02 / q04 / q03 四次选择、16 条路线、Normal / True 两个结局、affection / trust / truth_known 三个状态。q03 分别始终进入 Normal，q04 补救不抹去过去选择。需要改变角色关系或重大结局时，先把具体方案纳入创作审阅。

保持 15–30 个实际叙事场景，优先扩写已有场景；纯状态路由单独列出，避免拿节点数充当场景数。单路线建议 9,500–12,000 字，全分支正文 15,000–30,000 字。按 250–350 字/分钟粗估阅读部分约 27–48 分钟，再加正常选择和画面停留；只能标为估算，不能据此宣布时长验收通过。

| 章节 | 优先补足的体验 | 保持的事实边界 |
|---|---|---|
| 序章：雨夜 | 来取物的具体目的、站台行动与重逢过程 | 玩家知道信的作者；不把来到车站写成专程追寻女主 |
| 重逢 | 旧展览、各自近况与整理旧物的实际互动 | 关心与只谈事务有不同后果，女主有自己的生活 |
| 旧信 | 写信与离开的具体动机，坦白和暂缓各自的余波 | truth_known 只在女主获知事实时改变 |
| 空白 | 高 / 低信任下不同的交流过程与行动 | 两分支合流后知识、物品和时间保持一致 |
| 今天 | 旧照片、当下需要、补救或落实联系 | 表达不要求回报；补救改变接下来，不重写过去 |
| 雨停之前 | 同行 / 分别的完整收束与下一次联系 | Normal 也有完整人物弧线；True 保留双方主动性 |

默认资产预算：沿用现有站台、7 种表情和旧信 CG；新增最多 3 张背景（候车室、站内过道、雨停后的街角小店等按最终场景选择）和 1 张旧照片或结局 CG 候选。背景的实际地点、时间与剧情匹配；复用必须符合场景事实。每张保留源图、精确 Prompt、许可信息、版本、导入配方和哈希。
