## 导出流程

1. Windows 原生验收结束后，`tools.build.export_review` 继续完整审计五个真实进程、174 张 PNG 和实际 ZIP，并保留原格式的 `remote-audit.json`。
2. `tools.build.review_transport` 将机器 / 画面记录与 JPEG 检查副本分别写入封印包。按实际 JSON 和 base64 字节数分组，每个日志载荷最多 **4 MiB**；不依赖固定截图数量。
3. `game.yml` 上传封印包后调用 `export-review.yml`。记录任务验证完整目录并输出小记录；其输出生成动态截图矩阵，各任务只打印一个有界组。
4. 每个任务检查候选提交、原生来源 run ID、原始审计总哈希、文件集合、全部分组哈希、每张 JPEG 哈希及 PNG / 画面记录绑定。原始审计可逐字节重组；缺失、乱序、重复或篡改时拒绝导出。
5. 无需直接查看新图时，只输出记录并跳过空矩阵。单张图片或记录超限时明确失败，不降低分辨率、不丢图、不声称复核通过。

JPEG 是全分辨率检查副本；原始 PNG 的完整解码和哈希核对仍由 Windows 审计完成。传输脚本不替代原生交互、视觉审阅或真人检查。
