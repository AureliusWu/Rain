# v0.7 开发与恢复流程

此前独立 EXE 超时修复、Windows 全链路、第三章合流与第四章扩写均已完成；第五章、两个结局与三个场景背景也已形成候选。当前顺序：完整 Alpha 提交 → 新 Windows 源码 / 独立 EXE 验收 → 证据、哈希与候选记录 → 真人阅读计时 / 试听。

## 批次闭环

| 步骤 | 输出与完成条件 | 失败后从哪里恢复 |
|---|---|---|
| 1. 对齐现场 | 读最新 main、WORK_CHECKPOINT、VERSION；运行 preflight；保留来自其他会话的提交 | 先对齐远端，不按旧会话缓存覆盖正文 |
| 2. 小批次制作 | 只改 story.json；稳定 ID、配音、状态与路线；新增版本化 Scene Prompt | 保留已完成场景，下一批从未完成场景开始 |
| 3. 本地验证 | Prompt Registry、生成脚本、全文与逐路线统计、Python 与资产检查通过；Ren'Py lint 通过 | 修复失败项，不能只靠文件存在宣布通过 |
| 4. 提交与回读 | 一批文件形成提交；连接器 tree 与本地 tree 一致；main 普通快进；回读提交 | 不使用 force；远端变化时重新合并，避免覆盖聊天模式修改 |
| 5. Windows 原生验证 | 源码和临时解压 EXE 跑同一套完整交互用例；所有路线与 UI 证据通过 | 失败仍上传日志和已有截图；由失败的具体步骤继续 |
| 6. 证据与检查点 | 记录 commit、run、实际计数、ZIP SHA-256、截图和未完成项 | CI 绿后补齐记录，再进入下一批 |
| 7. 候选发布与人工验收 | main 仅验证并上传候选；手动发布重验选定提交；真人试听、阅读计时、普通电脑试玩单列 | 没有人工证据的项目保持待办 |

叙事事实检查由逐路线阅读完成。自动化能检查结构、状态、引用和脚本一致性，不能证明人物动机和情绪衔接成立。
